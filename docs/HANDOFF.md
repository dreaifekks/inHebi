## 用户做过的决定

这些是用户在使用后明确提出或拍板的，改动前先确认是否仍然成立。

- 列表：横版 4 列、竖版 5 列。没选 3 列是因为 Hanime1 缩略图原图只有 640 像素宽，放大会糊。
- 筛选条：聚焦即切换，焦点停留 0.4 秒后加载，不需要按确认。这推翻了 UX 规格里“按下才切换”的设计。
- 筛选条位置：左边是可横向滚动的芯片，最右边固定排序（或分级）和搜索。
- iwara 默认趋势，趋势排第一。芯片选择不跨启动记忆，每次打开都从第一个开始；右侧的排序、分级设置跨启动记忆。
- 漫画分类全部平铺在条上，子类写成“大类·子类”。
- 返回键：在网格里先回顶部并聚焦筛选条，再按才到顶部系统标签栏。
- 芯片不要勾号，用颜色表示选中，每个分类前有 SF Symbol 图标。
- 卡片上按播放/暂停键直接播放视频或直接进阅读器。
- 阅读器默认左键下一页（日漫从右往左），设置里可以改方向。
- 双页阅读两张图片按同一高度完整适配、内侧无缝拼接，整体居中，保留跨页图接缝。
- 双页从指定页开始配对：跳到或续读第 N 页显示 N/N+1，默认 N 在右、从左往右时 N 在左；每次前进/后退两页，不按奇偶对齐。
- 阅读页码在右下角，小而不抢眼；控制面板打开时预览页码也靠右、位于按钮行上方。
- 控制面板最底按钮行再按下，关闭面板并继续阅读。
- 卡片保留系统聚焦放大幅度，封面和标题留足空间；横版四列、竖版五列，按可用高度适配封面，首屏完整两行。
- 应用图标用概念 1“架上的书和播放屏”。另外两个概念的预览和全部源文件在 `artifacts/icon/`（被 gitignore，只在这台 Mac 上）。

## 工作约定

- 调试站点接口必须用 Swift URLSession 脚本。这台 Mac 上 curl 和 Python 会被 Cloudflare 拦下，结论会是错的。
- 不下载 tvOS 模拟器运行时，磁盘空间紧张。真机验证用局域网里已配对的 Apple TV 4K 第三代，tvOS 27。真机测试会实际占用客厅的电视，播放必须静音、只播几秒、结束后退出应用。
- Xcode 没有登录开发者账号。签名用 App Store Connect API 密钥，用户已明确同意这把密钥只用于本项目的签名和设备注册。密钥文件在 `~/Downloads`，取两个 AuthKey 里较新的那个；Key ID 和 Issuer ID 通过 README 里说的三个环境变量传入。密钥内容和这两个 ID、电视的设备标识都不能写进仓库。
- 截图里有成人站点的封面。核对版式时不要直接看原图：只截取顶部标签栏和筛选条那一条，或者先缩到 128 像素宽再放大成马赛克。注意 `sips -c` 的裁剪是从中心裁的，不是从顶部，曾经因此误看到封面；顶部裁剪要用 CoreGraphics 按左上角原点裁。
- 焦点问题先取真机焦点记录再改，取回方法在 README 的“DEBUG 焦点记录”一节。之前连续两轮真机测试全部通过，用户实际操作仍然不对，原因是测试只在加载完成后才按键、漏测了按上方向、也模拟不了触控面滑动。
- Codex 拒绝过成人站点的接口侦察类任务，但接受了应用开发本身。需要侦察新站点接口时派给 Claude。
- 写代码派给 Codex 时要说明不加多余的防御性代码。
